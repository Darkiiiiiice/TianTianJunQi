# 翻翻棋规则（fanfanqi）

> 状态：**已确认基础规则，局部交互为实测/推断假设**。
> 本文件是 `trainer/src/wgai/sim/` 的唯一规则来源；机器可读版本为
> `shared/rules/rules.json`，两者必须同步，规则改动必须升级 `rulesVersion`。
>
> 主要来源：
> - 腾讯《军旗翻翻棋》帮助页：<https://minigameimg.qq.com/help/rule222.html>
> - 天天军棋官网规则：<https://ttjq.qq.com/>
> - 2026-10 本机对局截图与 80 份棋盘快照的拓扑统计
>
> 当前版本：`fanfanqi-1`。责任链路：P0-5（规则确认）→ M2-2（规则实现）→
> M2-6（20–50 局真实回放零规则不一致）。

## 1. 棋盘

- 棋盘为 **5 行 × 12 列 = 60 格**（0-based：行 `0..4`，列 `0..11`）。
- 开局 **50 枚棋子（25/方）+ 10 个空行营**；行营开局为空，之后可以被棋子占据。
- 行营（绿色圆圈）坐标：
  `(1,2) (1,4) (2,3) (3,2) (3,4) (1,7) (1,9) (2,8) (3,7) (3,9)`。
- 行营是安全岛：敌方棋子不能吃行营中的棋子；行营中的棋子可以正常走出。
- 公路/铁路：
  - 普通格之间上下左右相连（公路一步）。
  - **行营只通过斜线与四个斜角格相连**（X 形道路），没有正上/正下/正左/正右的公路。
  - 铁路行：`0`、`4`；铁路列：`1`、`5`、`6`、`10`。
  - 铁路上的非工兵棋子只能沿同一条直线行走，不能在一个回合内转直角弯；
    工兵可以在铁路网中任意转弯。
- 邻接关系是**无向对称**的：若 A 能到 B，则 B 也能到 A。行营的斜线邻居
  同时把行营列回自己的邻接表，避免出现“能进行营、出不来”的有向图错误。

## 2. 棋子与数量

每方 25 枚，双方共 50 枚：

| 棋子 | 每方数量 | 军衔 | 说明 |
|---|---:|---:|---|
| 司令 | 1 | 9 | 最大 |
| 军长 | 1 | 8 | |
| 师长 | 2 | 7 | |
| 旅长 | 2 | 6 | |
| 团长 | 2 | 5 | |
| 营长 | 2 | 4 | |
| 连长 | 3 | 3 | |
| 排长 | 3 | 2 | |
| 工兵 | 3 | 1 | 可挖雷、铁路可转弯 |
| 炸弹 | 2 | — | 与任何棋子同归于尽 |
| 地雷 | 3 | — | 不能移动 |
| 军旗 | 1 | — | 不能移动，被扛即负 |

棋子标识使用英文 ID（与 Swift 分类器/`shared/schema` 对齐）：
`commander`、`army_commander`、`division_commander`、`brigade_commander`、
`regiment_commander`、`battalion_commander`、`company_commander`、
`platoon_commander`、`engineer`、`bomb`、`mine`、`flag`。

## 3. 开局与翻牌定阵营

- 50 枚棋子由系统随机放在 50 个非行营格上，全部背面朝上；行营为空。
- 双方轮流翻开一枚暗子。
- 当某次翻出的颜色与**上一张翻出的颜色相同**时，该次翻棋的玩家获得该颜色，
  对方获得另一色；随后进入走棋阶段。
- 走棋阶段先手：默认由**对手**（未翻出同色的一方）先走。该行为可通过
  `rules.firstMoveAfterFlip` 配置为 `opponent` 或 `flipper`；目前按
  `opponent` 实现，待真实回放校准。
- 翻牌阶段若 50 枚全部翻完仍未出现连续同色（极端情况），引擎按最后一枚的
  颜色分配阵营，由对手先走，避免卡死。

## 4. 行动

每回合只能二选一：

1. **翻棋**：翻开任意一枚暗子（走棋阶段也可以翻）。
2. **走棋**：移动一枚己方**已翻开**的棋子。

限制：

- 地雷、军旗不能移动。
- 不能吃己方棋子；不能吃行营中的敌方棋子。
- 走到空格、吃敌方明子、攻击敌方暗子都是合法尝试；暗子先翻开再结算。
- 工兵在铁路上可以沿铁路网任意转弯；其他棋子在铁路上只能直走。
- 吃子后**不额外获得回合**（`extraTurnOnCapture: false`）。

## 5. 战斗结算

### 5.1 明子对明子

- 军衔高者胜，低者被吃。
- 同军衔：双方同归于尽。
- 炸弹与任何敌方棋子相遇（包括地雷、军旗、炸弹）：双方同归于尽。
- 工兵 vs 地雷：工兵胜，地雷被排除。
- 其他棋子 vs 地雷：非法，不能主动碰触已翻明的地雷。
- 军旗：对方 3 颗地雷全部被清除后，任何棋子都可以扛旗；扛旗方立即获胜。
  炸弹扛旗时双方同归于尽，但军旗被夺，仍判进攻方获胜。
- 行营中的棋子不能被敌方吃；行营中的棋子可以主动出击。

### 5.2 攻击暗子

暗子的真实身份在翻开前对双方不可见。引擎按以下顺序结算：

1. 先翻开目标暗子。
2. 若暗子与进攻方**同色**：视为单独翻棋，双方都留在原地，不产生战斗。
3. 若暗子是**地雷**：
   - 工兵：工兵胜，地雷被排除；
   - 炸弹：同归于尽；
   - 其他棋子：进攻方阵亡，地雷保留并翻开。
4. 若暗子是**军旗**且对方仍有地雷：只翻开军旗，双方留在原地，不能扛旗。
5. 其他情况按 5.1 的明子规则结算。

以上 2–4 是当前实现的关键假设：

- `hiddenFriendlyRevealOnly`：同色暗子只翻开，不移动、不战斗；
- `hiddenMineKillsAttacker`：撞暗雷的非工兵/非炸弹进攻方阵亡；
- `hiddenFlagRevealOnly`：雷未挖光时暗军旗只能被翻开。

这些假设在 M2-6 真实回放中逐条核对；若与实际不符，只改引擎对应分支并升级
`rulesVersion`。

## 6. 胜负与和棋

满足任一条件即结束：

- **扛旗**：对方 3 颗地雷全部被清除后，用己方棋子吃掉对方军旗，立即获胜。
- **对方无棋可走**：轮到的玩家没有任何合法动作（没有可翻暗子，也没有可移动
  的己方明子），该玩家判负。
- **认输 / 超时**：真实客户端处理，模拟器不建模超时；认输记为对方胜。
- **80 步无吃子**：双方连续 80 步没有吃掉任何棋子，判和。当前实现从走棋阶段
  开始计数（翻牌阶段的翻子不计入），避免 50 次开局翻牌就把对局推向和棋。
- **300 步上限**：总步数达到 300，判和。
- **重复走棋**：同一玩家在**自己最近 8 步**内第 4 次走出完全相同的
  `(from, to)`，该玩家判负。翻牌不计入“走棋”。当前按“重复着法”解释
  （`repetition.basis = "sameMove"`），待真实回放确认是否应按“重复局面”判定。

## 7. 引擎实现约定

- 规则版本：`rulesVersion = "fanfanqi-1"`。
- 固定 seed 可复现开局；`GameEngine(rules, seed=N)` 的棋子位置与顺序完全确定。
- `Cell.revealed` 是可见性的唯一真相；`Piece` 只保存真实颜色与军衔。
- `Observation` 只暴露该玩家可见信息：暗子格不出现颜色/军衔；已吃子按颜色
  与军衔公开。
- `state_dict(player)` 输出 `shared/schema/game_state.schema.json` 兼容状态：
  - `turn` 是当前回合颜色；翻牌阶段尚未定色时用上一张翻出的颜色占位；
  - `legal_actions` 是可点击格子索引，已去重；
  - `last_move` 记录上一步走棋的 `from/to`。
- episode 目录：
  - `meta.json`：严格遵循 `shared/schema/episode.schema.json`；
  - `sim.json`：模拟器专用（rulesVersion / seed / firstPlayer / agents /
    outcome / colors / plies），不污染 `meta.json`；
  - `states.jsonl`：每个动作前一行 + 终局一行；
  - `actions.jsonl`：`kind/from/to/cell/combat/captured/revealed/outcome`；
  - `reward.json`：双方回报（胜 +1 / 和 0 / 负 −1）。
- 真实录制回放同时支持模拟器动作格式与
  `shared/schema/action.schema.json` 的 `tap_cell`；`tap_cell` 用动作前状态
  里的 `selected` 推断走棋起点。

## 8. 待真实回放确认

M2-6 用 20–50 局真实对局逐条核对，重点：

- 同色暗子被攻击时是“只翻开”还是其他处理；
- 暗雷被非工兵/炸弹攻击时进攻方是否必死；
- 雷未挖光时暗军旗是否只能翻开；
- 翻牌定阵营后的先手方；
- 80 步无吃子是否包含翻牌阶段；
- 重复走棋按“同一着法”还是“同一局面”判定；
- 真实客户端是否在吃子后额外给回合。

在这些问题被真实数据确认前，`fanfanqi-1` 的对应分支都视为**可替换假设**，
不得当作不可变的规则真理。
